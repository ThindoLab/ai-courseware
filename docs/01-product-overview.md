# 产品梳理：用户、问题、服务

> 实现与目录以 `docs/04-architecture-design.md`、`pi/教练.md`、`DIRECTORY.md` 为准。本文是早期产品背景。

## 1. 目标用户

### 双向角色：人人可使用，也可创作

| 用户 | 角色 | 需求 | 付费意愿 |
|------|------|------|----------|
| **家长** | 使用 / 轻创作 | 晚间辅导讲不清，要可视化图解；偶尔自制分享 | 中（为孩子教育） |
| **教师** | 使用 / 轻创作 | 低成本互动页，电子白板直接用；优质内容可外部分享 | 中 |
| **教育机构** | 使用 / 机构创作 | 快速出试听/宣传互动材料 | 中高 |
| **AI 副业/内容创业者** | **细分场景构建者** | 基于框架做 Skill 与内容，外部售卖，不从零开发平台 | 低门槛试错，靠内容变现 |

**核心判断**：系统提供框架 + 基础 Skill；创作者补长尾场景；前期共享以文件/开源方式发生，不先做交易平台。

---

## 2. 解决的问题

| # | 痛点 | 解法 |
|---|------|------|
| 1 | 制作成本高 | Skill 模板化 + AI 生成 |
| 2 | 内容枯燥 | 可交互 HTML，一点就变 |
| 3 | 技术门槛高 | pi agent 调度，创作者只关心场景与知识 |
| 4 | 长尾覆盖不足 | UGC/创作者扩展 Skill 与内容 |
| 5 | 副业不知从哪切 | 给出 MVP 场景与模板，快速验证 |
| 6 | 难差异化 | 原子教具，不做大而全课堂平台 |

---

## 3. 提供的服务

### 3.1 创作框架（核心）

- **创作引擎**：pi agent SDK（工具调用、工作流、MCP）
- **Skill（单一概念）**：按**类型/模板**编排大致工作流，Agent 执行中可调工具/MCP
  - 内置类型先做：参数图解 / 选择分支 / 拖拽槽位
  - 系统提供基础 Skill；创作者可新增同类型或扩展类型
- **基础能力**：知识检索策略、基础工具、单文件 HTML 导出

### 3.2 内容生成

面向单考点原子教具，不先做整课：
- 数学图解（行程/分数/鸡兔同笼/图形变换等）
- 英语句型槽位
- 故事/安全分支情景
- 学前轻互动

### 3.3 内容承载

- **目前只做单文件 HTML**
- 电子白板 / 浏览器直接打开
- 自包含，尽量离线可用

### 3.4 共享与变现（阶段化，口径统一）

| 阶段 | 做什么 | 不做什么 |
|------|--------|----------|
| **前期验证** | 框架 + 基础 Skill + 导出 HTML；创作者拿成品去小红书/微店等**外部售卖** | 不做平台内交易、不做账号付费墙 |
| **验证成功后** | 再考虑平台内共享市场、订阅生成额度 | — |

前期平台侧可免费/低成本提供生成能力做引流；  
**收费主体先在创作者外部成交**，不是我们先建商城。

---

## 4. 差异化

- 开放 Skill，不做封闭内容工厂
- 单考点原子 HTML，电子白板友好
- 知识层按模块控质量（学习辅导优先本地教材）
- 创作核心用 pi agent，能力可扩展（工具/MCP）
- 站在 OpenMAIC/老师帮验证过的需求上，**裁剪成更窄产品**

---

## 5. 与 OpenMAIC / 老师帮的关系（一句话）

| 项目 | 关系 |
|------|------|
| **OpenMAIC** | 参考实现：交互 widget 契约、HTML 后处理/内联导出、两阶段生成思路；**不 fork 整仓**，不重做多智能体整课 |
| **老师帮** | 商业验证：数学可视化 + 一句话生成路径成立 |
| **ChinaTextbook** | 教材素材来源，需自建检索，不是开箱知识库 |
| **pi agent SDK** | 我们的创作调度核心 |

详见 `03-resources-research.md`。

---

## 6. 推广方向

小红书种草关键词：
- 除了死工资，发现的副业：AI 课件
- 家庭辅导 / 上课互动页 / 宣传试听
- 工具和案例都有了，就差细分场景创业

主打：**低成本、可交互、可导出、可复制**
