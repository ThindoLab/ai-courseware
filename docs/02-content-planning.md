# 内容选型与 Skill 设计

> 实现现状以 `samples/`、`pi/教练.md` 为准。

## 1. 按品类调研家长需求优先级

判断标准（比单纯“热门”更重要）：
1. **台前讲不清**：家长/老师自己会做题，但讲不明白
2. **需要体感/动态**：纸笔难画过程（行程、变换、分数分割）
3. **高频刚需**：周频作业/预习/班会反复出现
4. **适合原子 HTML**：一个文件讲清一个难点
5. **交互可复用**：能沉淀成固定 Skill 模板

> 以下优先级按**辅导抓手难易**排序，不是按学科完整度排序。  
> 一手样本主要来自**小红书高赞笔记 + 中文新闻/搜索结果**；X（Twitter）上中文「家庭辅导/AI课件」讨论密度低，参考价值有限，见下节。

## 1.0 一手调研：家庭辅导 & AI 课件场景

### 样本来源与局限

| 来源 | 结果 | 结论 |
|------|------|------|
| **小红书**（关键词检索，按点赞排序，近一年） | 样本丰富、情绪强、场景具体 | **主数据源** |
| **中文新闻/搜索** | 「9 成家长辅导崩溃」、AI 学习机/家教机、九章 AI 交互课件等 | 验证刚需与竞品形态 |
| **X / Twitter** | 中文家长辅导长帖稀少，难形成稳定话题簇 | **不作主依据**；英文区更偏 general homework help / AI tutor，不等于国内 K12 场景 |

### 家庭辅导：高频痛点（小红书）

高赞标题反复出现同一情绪结构：**不是不想管，是管了就崩 / 越教越懵**。

| 信号 | 代表内容（点赞量级） | 产品含义 |
|------|----------------------|----------|
| 辅导即崩溃 | 「哪有家长辅导作业不疯的」14w+；「我可以为孩子付出生命，但就不能辅导作业」5w+ | 要的是**救场工具**，不是再增加家长备课量 |
| 越教越懵 | 「为啥现在家长辅导作业，越教越懵？」5w+ | 缺**可视化抓手**，不是缺答案 |
| 高学历也崩 | 「研究生爸爸辅导女儿小学数学崩溃大哭」 | 难点在**讲解表达**，不在知识本身 |
| 降本降怒 | 「含泪分享：数学辅导终于不费妈了」「选对工具有多重要」 | 工具若能 30 秒讲清，付费/传播都成立 |
| 磨蹭/情绪次生问题 | 「一招治孩子做作业拖拉磨蹭」 | 次生问题多，但**第一刀仍应打在讲不清** |

新闻侧交叉验证：
- 「9 成家长辅导作业崩溃」类报道长期存在
- 作业帮/点读机/家庭辅导机器人等硬件叙事，说明市场在抢「作业战争」
- 豆包爱学等做家庭辅导短片，心智是**对话讲题**；我们要差异化成**可点教具**

### 数学：最强「讲不清」簇

| 细分 | 社区信号 | 适合做成 |
|------|----------|----------|
| **鸡兔同笼** | 「混子哥边画边讲」「7 种解法动画」「假设法」多条过万赞 | 参数联动（头/腿）+ 假设法演示 |
| **行程问题** | 「认真画图分析」「比例法」「相遇问题拓展」高收藏向 | 动态路径/参数模拟 |
| **线段图 / 和倍差倍** | 「和倍问题线段图」「倍数问题」老师与家长号都强 | 交互线段图 |
| **分数** | 「分数学习不用背」「分数拆分难题」 | 可拖分割 / 图解 |
| **图解法总论** | 「孩子应用题读不懂？试试图解法」 | 统一「图解」心智，利于种草 |

→ 数学仍是 **S 级主战场**；内容不是题海，是**图解装置**。

### 英语 / 拼音：家长能力短板簇

| 细分 | 社区信号 | 适合做成 |
|------|----------|----------|
| **英语句型/语法** | 语法体系笔记高赞；「娃写英语句子终于不瞎编」 | 拖拽槽位句型 |
| **亲子英语短句** | 「在家英语启蒙高频短句」 | 轻量槽位/卡片 |
| **拼音口音** | 「家里口音不标准，拼音到底怎么启蒙」「家长教拼音大坑」 | 拖拽组合可以做，但**发音校验要谨慎**（容错中） |

→ 英语句型仍适合 S；拼音可做交互，但不要承诺「纠正发音权威」。

### 低龄 / 故事 / 安全

| 细分 | 社区信号 | 适合做成 |
|------|----------|----------|
| **幼小衔接认数** | 「到底怎么教会孩子认识数字」「幼小衔接数字怎么学」多条高赞 | 点选/拖拽轻互动 |
| **童话互动** | 童话体验/绘本讲解/情景剧剧本热度高 | 选择分支叙事 |
| **消防安全教育** | 班会/道法/情景表演有需求，但爆款弱于作业崩溃 | 情景选择树（A 级，学校场景补位） |

### AI 课件 / 互动课件：供给侧在热什么

小红书里「AI 课件」当前更偏 **教师备课 PPT**，不是家长原子教具：

| 热门方向 | 代表信号 | 对我们的启发 |
|----------|----------|--------------|
| AI 做 PPT / 公开课 | 「年轻老师一定要用 AI 做课件」3w+；赛课/公开课模板 | 老师侧流量大，可作**分发入口** |
| AI 互动/游戏网页 | 「学生抢着答！1 分钟生成游戏网页」；「AI 赋能生成完整课件+课堂互动小游戏」 | **互动网页**已被验证有传播点 |
| 希沃/电子白板课件 | 「希沃制作可互动式课件」「小学英语课件神器希沃」 | 交付要贴合**白板打开即用** |
| 垂类教育 AI 备课 | 「这个垂类教育 AI 火了，帮老师轻松备课」 | 垂类比通用更易种草 |

新闻侧补充：
- 「一句指令生成 AI 交互课件」（九章爱学老师版）→ 老师端商业路径已通
- 大量「AI 课件 PPT 神器」→ 红海在 PPT；**蓝海在可点 HTML 教具**

### 调研结论 → 选型修正

```text
家长侧爆点：辅导崩溃 / 越教越懵 / 数学图解 / 不费妈工具
老师侧爆点：AI 备课 / 公开课 / 互动游戏页 / 希沃白板
AI课件现状：PPT 红海，交互网页开始起量，家长原子教具仍稀缺
X 平台：中文家庭辅导讨论不足，不作为优先级主证据
```

产品含义：
1. **第一用户叙事**仍可双线：家长「今晚别崩」+ 老师「白板可点」
2. **MVP 内容**继续押数学图解；英语句型次之；故事/安全作传播侧翼
3. **不要**和「AI 出 PPT」正面卷；话术站在「可交互教具 / 图解讲清」
4. 竞品心智（学习机/豆包讲题）是**给答案**；我们是**一起点懂**

## 2. 场景补充：公开讨论里更“缺抓手”的点

结合 **§1.0 一手调研**、OpenMAIC 交互能力，额外锁定这些高价值切口：

| 场景 | 为什么难辅导 | 推荐交互 | 建议阶段 |
|------|--------------|----------|----------|
| **今晚这道应用题** | 不是缺题库，是缺 30 秒讲清 | 参数图解 / 线段图 | MVP |
| **公开课/试听要“看得见效果”** | 老师要 aha，不是翻页 PPT | 单难点交互页 | MVP 后 |
| **班会安全教育** | 说教无体感 | 选择分支 | A |
| **低龄睡前/亲子共读** | 每天找故事累 | 分支叙事模板 | A |
| **编程思维第一课** | Scratch 太重，怕冷场 | 顺序/循环可视化（后置） | B |
| **立体几何空间感** | 纸模慢、脑子转不动 | 3D/展开（可参考 OpenMAIC visualization3d，但先不做默认） | B |

## 3. 与 OpenMAIC Widget 的映射（避免重复造轮子）

OpenMAIC 源码里 interactive 已拆成 6 种 widget。我们**不照搬全部**，只映射到原子教具：

| 我们的 Skill type | 对应 OpenMAIC Widget | 取舍 |
|------------------|----------------------|------|
| **param-visual 参数图解** | `simulation` | **优先做**。直接服务数学/科学参数关系 |
| **branch-story 选择分支** | `game(strategy)` + 轻量叙事结构 | **优先做**。服务故事/安全/决策 |
| **drag-slot 拖拽槽位** | `game(puzzle)` / 部分 diagram | **优先做**。服务英语句型/拼音/排序 |
| 过程揭示图 | `diagram` | 第二阶段 |
| 步骤操作 | `procedural-skill` | 安全/急救可后置 |
| 3D / 代码沙箱 | `visualization3d` / `code` | 明确后置，过重 |

OpenMAIC 还给了硬约束可直接继承：
- 触摸热区 ≥ 44px
- 移动端控件不挡主视图
- 自包含 HTML + 配置 JSON
- 重置必须回到初始状态

## 4. MVP 优先级（收窄）

S 级不能铺太开。第一刀只做下面 3 条线：

```text
MVP-1  数学图解（和差倍 / 行程 / 分数 / 鸡兔同笼 / 图形变换）
       → Skill：参数图解

MVP-2  英语句型槽位
       → Skill：拖拽槽位

MVP-3  童话/安全分支叙事（二选一先验证）
       → Skill：选择分支
```

| 优先级 | 内容 | Skill |
|--------|------|-------|
| **S / MVP** | 小学数学图解核心题型 | 参数图解 |
| **S / MVP** | 英语句型训练 | 拖拽槽位 |
| **S / MVP** | 童话互动 或 消防情景（先做一个） | 选择分支 |
| **A** | 拼音识字、成语寓言、钟表方位、周长面积 | 三类模板扩展 |
| **B** | 文言、古诗、3D 立体、编程思维、益智合集 | 后置 |

## 5. 三类基础 Skill 类型（type）

> Skill = **可编排工作流**；type 决定默认流程骨架 + HTML 交互契约。  
> 同一 type 下可有多个 Skill 实例（如「行程」「鸡兔同笼」都属参数图解型）。

### 类型 1：参数图解 `param-visual`
- **场景**：数学概念、行程、分数、鸡兔同笼、面积
- **交互**：滑条/步进器改参数 → 图与结论实时变
- **成功标准**：孩子拖两下能自己说出关系

### 类型 2：选择分支 `branch-story`
- **场景**：童话、寓言、消防/防拐、题意理解
- **交互**：点选项推进 → 对错/后果即时反馈
- **成功标准**：比纯说教记得住，30 秒出 aha

### 类型 3：拖拽槽位 `drag-slot`
- **场景**：英语句型、拼音组词、步骤排序
- **交互**：拖到槽位 → 对错高亮
- **成功标准**：家长不用讲语法也能陪练

## 6. 内容模块划分（与架构对齐）

| 模块 | 覆盖内容 | 知识来源策略 |
|------|----------|--------------|
| `learning-coaching` | 小学数学/语文/英语学习辅导（核心） | **本地教材优先** → 权威教育站 |
| `preschool` | 学前认数形状、趣味识字、亲子故事 | 启蒙读物 + 教育站 |
| `safety-life` | 消防/防溺水/居家安全/急救 | **官方安全站优先** |
| `story-culture` | 童话、成语寓言、传统节日 | 本地读物/教材 + 权威百科 |

> 英语与语文学习归 `learning-coaching`；童话故事归 `story-culture`，避免和“课内辅导”混入口。

## 7. 三个落地难点

| 难点 | 原则 |
|------|------|
| **Skill** | 先做 3 个固定交互契约；LLM 只填内容，不自由改结构 |
| **数据来源** | 学习辅导优先本地书籍/教材索引；其他模块白名单外搜；质量优先于数量 |
| **呈现** | 只做单文件 HTML；电子白板点开即用；大按钮、少菜单、可离线 |

## 8. 启动路线

**第一阶段（验证）**
1. pi agent SDK 创作主循环
2. 3 个基础交互 Skill
3. 数学图解 8–10 个样例 + 1 个非数学样例
4. 电子白板/浏览器实机打开验证

**第二阶段（扩展）**
1. 创作者可加领域 Skill
2. 知识层本地检索可用
3. 外部售卖路径跑通

**第三阶段（平台化）**
- 再考虑共享市场与订阅
