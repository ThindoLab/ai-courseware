# 分批迭代台账

## 怎么记（每轮四栏，缺一不可）

| 栏 | 写什么 |
|----|--------|
| **版本** | slug、vN、`aid-iteration`、页头 note、历史路径 |
| **反馈** | 用户对**该 vN** 的原话（不混旧版） |
| **检查** | 对着该版 HTML 核对：属实 / 部分 / 已过时；证据一句话 |
| **优化** | 本轮改了哪条**系统通则**（不点名单篇题面）；是否重跑；下一轮动不动 |

流程：改通则 → `node scripts/rerun-create.mjs --iter=RN <slug…>` → 新 vN 入库 → 填本表「优化」→ 用户审 → 填「反馈 / 检查」。  
冲突或漂移：同一 slug 上下两轮对照。整页重跑换皮记在「检查 / 漂移」。  
大纲与注意事项：[\_迭代须知.md](_迭代须知.md)。
