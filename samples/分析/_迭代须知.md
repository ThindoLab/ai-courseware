# 分批迭代：大纲与注意事项

对照台账：[\_迭代.md](_迭代.md) · 反馈协议：[../反馈.md](../反馈.md) · 锁皮：[../../pi/memory/keep.md](../../pi/memory/keep.md)

本文沉淀 R1–R4 之后怎么迭代。新一轮动手前先读这一页。

## 1. 这一套在干什么

用用户观感反推**问题类型**，改提示词 / 角色 / `qa_check`，再 `CREATE_FORCE_LLM` 重跑少数篇。  
**质量来源是生成链路，不是手改 `samples/<slug>.html`。**

目标：补「做不完 / 看不清 / 演示骗人 / 揭晓被盖」。  
不是把所有待改刷到同一完成度，也不是整库重跑。

## 2. 一轮怎么走（大纲）

```
记反馈（原话 + 版本号）
  → 检查该版 HTML / 截图（属实？旧版差评是否过时？）
  → 收成一条不互斥的问题类型（不要点名单篇题面）
  → 写入 图解 / _CORE / writer / qa；能自动拦的进 qa_check
  → keep.md 锁住已经认好的皮和结构
  → 用户点头后：rerun-create --iter=RN <少数 slug>
  → 台账填「优化」；打开新稿给人审
  → 审完填「反馈 / 检查」；好评拆可复用；差评进下一轮类型
```

命令：

```bash
# 默认会选 deepseek-v4-flash；402 余额不足时显式换会写工具的模型
AGENT_MODEL=grok-4.5 AGENT_TIMEOUT_MS=600000 \
  node scripts/rerun-create.mjs --iter=R5 color-sort
```

成功：覆盖 `samples/<slug>.html`，历史进 `samples/versions/<slug>/vN.html`，页头盖 `aid-iteration`。

## 3. 台账四栏（缺一不可）

| 栏 | 写什么 | 不要写成 |
|----|--------|----------|
| 版本 | slug、vN、`aid-iteration`、历史路径 | 「最新稿」不写号 |
| 反馈 | 用户对**这一 vN** 的原话 | 用旧版差评盖新版 |
| 检查 | 对着该版 HTML：属实 / 部分 / 已过时 + 一句证据 | 「感觉差不多」 |
| 优化 | 改了哪条**系统通则**、跑没跑、下一轮动不动 | 只写「重跑了」 |

好评也要拆：可复用点写进该条记录，必要时同步 `keep.md`。同时写清：锁什么、还不改什么、若动只动哪一类。

## 4. 选篇规则

- **一轮一类问题，少篇。** 2 篇封顶为宜。整库 `FORCE_LLM` 禁止。
- **可用 / 整篇锁住的不跑。** 现在：average、there-be、compare-length、clock-read、fraction、stranger-door、pattern-lights v7、color-sort v8。
- **局部锁住的若跑，只动未锁部分。** 写进本轮通则和 keep，禁止整页换场景。
- **残页不当模板微调。** chicken-rabbit 审 v1，不要在 v2 残页上堆。
- **没点出具体坑的先冻。** 如 balance-scale。
- 待改但未进台账的篇：先有反馈和 `分析/<slug>.md`，再排队，不要为了「推进」扫进去。

## 5. 通则怎么写才算落地

| 做法 | 结果（R1–R4 见过） |
|------|-------------------|
| 只在提示词里写「用镂空环」 | 模型照抄旧 `demoCheck` 实心牌，`qa_check` 还是过 |
| 问题定名 + `qa_check` error | R4 揭晓章第一次被拦住，v7 引导变成镂空环 |
| keep 只写「开场动画」 | R3 整页换成竖串小熊，样式回退 |
| keep 写死「夜空横串 + 狐狸，禁止竖串」 | R4 皮回来了 |

所以：

1. **类型名要能指着屏幕说出来**（例：揭晓章盖住答案 = 不透明方牌 + ✓ 压住刚出现的灯）。
2. **演示层和玩的层同一条。** 玩对了、引导仍盖住，算没过。
3. **能静态扫到的必须进 `qa_check` error**，不要只靠写手自觉。
4. **认好的皮写进 keep，写清禁止换什么。** 空泛的「保留气质」拦不住换皮。

## 6. 对抗反思（每轮对着问）

- 会不会把已经清楚的图解、安全红线、一屏结构改差？
- 这一改是类型规则，还是在给某一篇写死题面？
- 新稿是否整页换皮？换了要在「检查」里写漂移，等用户认，不要当默认胜利。
- 旧版差评在新版是否已经过时？过时的不要再当现状。
- 用户说「很不错 / 非常好」时，下一动是否只动他们点名的那一类？

宁可少改。当前库整体好于更早的整库重跑。

## 7. 模型与失败

- 宿主只选会调 `write` 的模型。`claude-fable` 禁用。
- `deepseek-v4-flash` 曾能跑通；**402 Insufficient Balance** 时不要空转，换 `AGENT_MODEL=grok-4.5`（或其它已冒烟能回字的）。
- Anthropic 若 401 Invalid bearer token，不要用 haiku/sonnet 硬试。
- `assistant stop=error` 且 `content=[]`：先看 `errorMessage`，再换模型。不要把旧 output 里的 HTML 冒充本次生成。
- `maxTokens` 创建链路已抬到 ≥32000，不要再降回去。

## 8. 已沉淀的问题类型（写提示词时用这个名字）

| 类型 | 孩子看见什么 | 一律怎么写 | 检查 |
|------|--------------|------------|------|
| 演示≠玩 | 演示一套皮，进场认不出 | 同一套主图组件 | 提示词 |
| 演示答案打架 | 演出来的结果和规律相反 | 演示答案须能用本场规则算出来 | 提示词 |
| 填入被盖 | 问号圈压住刚填入的字/灯 | 填入后拆提示层 | 提示词 |
| 揭晓章盖住答案 | 不透明绿对号牌盖住答案 | 镂空环；对号放旁边 | **`reveal-cover` error** |
| 主槽塌掉 | 车厢/格子宽高为 0 | 明确最小宽高 | 提示词 |
| 图色≠判定色 | 红车判进蓝筐 | 看见的主色 = 判定色 | 提示词 |
| 拖到槽下面 | 苹果钻进筐底色 | 拖拽物在槽之上，父级不裁 | 提示词 |
| 待投放物叠死 | 鱼堆在角落，看不见、不会动 | 铺在舞台中间、彼此分开；有生命的可轻微游/晃，不要阅兵、不要叠成一坨 | 提示词（R5） |
| 关卡卡死 / 下一步被裁 | 第一关做完没下一关 | 每关能前进；按钮留在当前屏 | `ux-next` 等 |
| 假举一反三 | 换了一套认不出的符号 | 只换数/色/物 | 提示词 |

## 10. R1–R4 一句话

| 轮 | 通则 | 结果 |
|----|------|------|
| R1 | 演示=玩、答案自洽、填入不盖、每关能前进 | 4 篇；fraction / stranger-door 停跑 |

| R4 | `reveal-cover` + 锁夜空横串 | pattern v7「非常好」，整篇锁住 |
