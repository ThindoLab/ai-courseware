# Roadmap

覆盖范围：**验证期（Phase 1–6）+ 扩展期（Phase 7–8）**。平台化（共享市场 / 订阅）列入 Later，不展开。

---

## Phase 1: HTML 交互契约 ✅

**目标：** 手写 3 类模板（参数图解 / 选择分支 / 拖拽槽位），证明交互在浏览器和电子白板可用，不依赖任何 LLM。

- 每类模板有一个可打开的 .html 样例
- 断网可用，触控热区达标
- 对应 schema.json 存在且能手工校验

---

## Phase 2: 内容注入与校验工具链 ✅

**目标：** `content.json` -> 单文件 HTML 的确定性流水线跑通，注入失败不产出"半成品"。

- `html.inject` / `html.validate` / `html.inline` 可用
- 契约测试套件覆盖 3 类模板 fixtures
- CLI 一键从内容到输出：`create-from-content`

---

## Phase 3: 知识层最小闭环 ✅

**目标：** 学习辅导路径优先命中本地知识点，结果带来源标注，可被工具独立调用。

- 本地文本切片（数学核心题型 ≥ 5 篇，MVP 手写占位，非真教材 PDF）
- grep 检索接口：`knowledge.search({ query, module })`
- 模块策略生效：`learning-coaching` -> 本地优先
- 未命中时行为明确（报错 / 降级，由 Skill 配置决定）

> 此阶段知识层作为独立工具可测，尚不接 Agent；真教材 PDF 提取后置。

---

## Phase 4: 后端 API + Agent 主循环 ✅

**目标：** 一条文字请求经后端调用 pi agent SDK，端到端产出可下载的 HTML（知识层可调）。

- 后端 API 接收 `{ topic, module, skillId? }`（不指定 skillId 走默认匹配）
- Skill 注册表加载，steps 按配置编排
- Agent 可调用 Phase 3 的 `knowledge.search`
- 工具白名单生效，越权请求失败
- 输出含 `report.json`（来源、校验状态、体积）

---

## Phase 5: 前端入口 ✅

**目标：** 有一个页面可以输入需求、选 Skill、触发生成、下载教具。

- 文本输入框 + Skill 选择器（不选走默认匹配）
- 调用后端 API，展示生成状态
- 下载单文件 .html
- 不做用户登录 / 历史记录

---

## Phase 6: 样例包与实机验收 ✅（实机待测）

**目标：** ≥ 10 个教具契约校验全绿，电子白板触控验证通过，可对外演示。

- 数学样例 ≥ 8（鸡兔同笼 / 行程 / 分数 / 和倍 / 周长面积 / 图形变换 …）
- 英语拖拽槽位 ≥ 1
- 分支故事（安全或童话）≥ 1
- 单次生成 ≤ 2 分钟（抽样验证）
- `validate-all` 批跑无红
- 至少一次平板 / 白板实机记录（截图或录屏备注）

---

## Phase 7: 创作者扩展 Skill（扩展期） ✅

**目标：** 创作者能同 type 零代码新增 Skill 实例，不改内核即被发现使用。

- 新增 Skill 的目录与配置规范文档化（SOP）
- 注册表自动发现新 Skill
- 至少 1 个创作者自建实例跑通端到端

---

## Phase 8: 外部售卖路径（扩展期） ✅（分发=免费分享；售卖不适用）

**目标：** 创作者能把生成的教具打包，在小红书 / 微店等外部渠道售卖的路径跑通。

- 教具打包（单文件 + 说明 / 预览图）
- 售卖 SOP 文档
- 至少 1 个样例完成外部上架试水

---

## Later / Backlog

- FireCrawl 白名单外搜（知识层增强）
- PDF 教材批量切片与索引升级
- 共享市场 / 订阅生成额度（平台期，需先有验证数据）
- 移动端原生 App
